# Product UI copy and controls

For every visible paragraph, field and label, ask: “What does the user need this for at this moment?” Remove content without a useful answer. Preserve useful field labels, units, error recovery and decision-relevant uncertainty.

Follow `specs/ui-composition.md`: identify each surface's primary task and every action's scope (workspace, collection, selection or item). Group by task/frequency; specify placement before adding controls. Coordinator owns shared composition. Keep browsing tabs/search/filters together, save actions with selected evidence, and collection management consistently reachable. Rare layout actions belong in a labeled menu. No arbitrary toolbar quotas or icon-only conversion rules.

Repeated rows use consistent identification and aligned comparison fields. Keep headers/tabs outside the content scroller with shrinkable ancestors; fix the overflow cause rather than clipping content. Existing panel state, project evidence, accessible default components and preset decisions below take precedence over generic examples.

- Keep extraction, deduplication, workbook-linking and implementation commentary in repository documentation. Never render `dataset.coverage.notes` wholesale in product screens. Preserve raw records and exports; use curated presentation helpers for known ingestion notes, retaining unfamiliar imported notes.
- Do not display `generatedAt` as freshness. Show a concise source edition/date only when grounded in actual sources. Preserve historical planned/need-date meanings; local saved dates are useful history, not source freshness.
- Keep missing locations, confidence and material limitations beside the affected result. Keep phase-date exceptions with the relevant project, including Dawson. Explain methodology and source background once in a clearly named, curated details view, never a disclaimer dump or a large popover.
- Show counts only for browsing, filtering, selection or active coverage. Avoid repeated instructions, metadata, empty-field filler and repeated real/demo paragraphs; retain a clear mode label wherever needed to interpret the content.
- Familiar close, previous/next, zoom and contextual panel toggles can be icon-only. Remove redundant visible text, use `IconButton` for accessible names plus hover/focus tooltips, preserve disabled/active states and shadcn default hit areas. A native `title` alone is not a keyboard-focus tooltip.
- Keep visible text for destinations, domain actions, destructive/recovery actions and distinctions an icon cannot explain. Reuse Lucide consistently; decorative icons are hidden from assistive technology. Do not decorate result rows.
- Preserve the current shadcn preset, readable defaults and viewport-contained layout with internally scrolling panels. Follow the repository's bounded checking policy; no visual checks.
- Map controls anchor to the map container, independently of changing panel insets; keep those insets for geographic fitting and attribution. Legend symbols keep text labels, portalled overlays isolate map events, and secondary help stays in bounded, internally scrolling content. Preserve Radix keyboard dismissal/focus return and default component styling.
- Zoom in, Zoom out and Fit use the same explicit IconButton preset size and outline treatment in both map renderers. Group zoom semantically without an extra padded frame that changes its apparent height. Report background-resource and project-layer failures separately; retain genuine errors and recovery actions.
- Explore uses one results/detail panel with explicit Back and Expand controls. Do not reintroduce a separate comparison pane. Selection and Back must not clear query/filters or change the result tab/page/scroll; preserve drafts through navigation, collapse and tab changes. Retain inactive views without exposing hidden controls to focus. Motion must respect reduced-motion preferences.
- Keep the panel's search slot, width and header inset consistent across Results/Detail/Collapsed. One persistent tooltip-backed square chevron toggles expansion beside search, retaining manual keyboard focus on that same trigger; Back and selection retain their separate focus behavior. Shell radius may account for the nested inset using local preset radius values; shared Input/Button/theme styling stays intact.
- The comparison body is embedded in the floating panel and has square corners. Override its Card radius locally; preserve the outer panel radius and shared shadcn Card defaults.
- Keep result counts in browsing tabs, pagination and selected comparison context; omit the repeated count from the persistent/collapsed search header.
- Home explains audience/problem/benefit/entry concisely; Outcomes explains evidence-supported conclusions and next actions against the applied scenario. Neither is a second explorer or a savings scoreboard. Preserve workspace instances across destination changes. Project scope, budgets, proximity and resource-sharing questions never establish realized benefit or current status.

- F28 geographic enrichment is a separate evidence layer. Label approximate points and areas by method/precision, retain unresolved reasons and source/demo distinctions, and never present area extents as exact project points or exploratory proximity as strict candidates/coordination benefit. All imported rows remain accessible; coverage must distinguish unprocessed from unsupported or ambiguous outcomes.
