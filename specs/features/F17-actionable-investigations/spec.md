# F17 — Save an actionable investigation

Purpose: turn an interesting pair into an evidence-backed handoff and make its assumptions understandable when revisited.

Inputs: current saved-opportunity schema, candidate/project evidence, review drafts, ImpactDraft and canonical estimateImpact. Missing enabling work: additive optional investigation fields, capture of impact assumptions from the single detail owner, migration-safe persistence and inclusion in TXT/JSON exports.

Owner: ui after F15, coordinated with core for the storage/impact contract. Own features/briefs/* (except F18 restore module/component), ComparisonPanel.tsx and ImpactPanel.tsx only after explicit handoff. Coordinator owns schema contract and consumer composition. Depends on F06/F07/F14 and the F15/F16 navigation integration. Keep increments separate: investigation objective/next question first, then saved impact scenario and export.

## Agreed additive contract and handoff
- Core owns `briefs/storage.ts` and `briefs/export.ts` for this increment. Export `Investigation`, `investigationSchema`, `EMPTY_INVESTIGATION` and the existing `savedOpportunitySchema`. Investigation fields: `resource` enum (`unspecified`, `right-of-way`, `crews-equipment`, `substation-capacity`, `other`), `objective`, `nextAction`, `owner` strings, and `impactInputs: ImpactInputs | null`. SavedOpportunity adds optional `investigation`; old v1 stores/briefs remain valid. Validate impact input bounds consistently with the existing core. Snapshot refresh preserves investigation.
- JSON exports retain investigation/inputs and add the canonical derived impact result when valid inputs exist; text exports label the objective, next action, analyst and hypothetical assumptions/result. Never trust an imported result over its inputs. Core does not edit BriefWorkspace or calculator UI.
- UI owns `BriefWorkspace.tsx`, `ComparisonPanel.tsx`, `ImpactPanel.tsx` and `Explorer.tsx` after F15/F16 composition integration. Review drafts include an Investigation default for legacy records, and refresh/navigation preserve dirty fields. ImpactPanel adds optional `onSaveScenario(inputs: ImpactInputs)`, enabled only with a valid result; ComparisonPanel forwards an optional callback. Explorer passes an explicit pair-ID/request/inputs payload to its single BriefWorkspace instance, which saves only the matching current pair and updates that review's impact inputs without erasing draft notes/questions. Exported files represent saved work; unsaved changes stay labeled.
- No App, domain Dataset, math, real data or dependency edits. F18 may begin against the storage contract once integrated while the UI slice finishes. UI owns the final F17 receipt; core's additive intermediate PR needs no completion receipt.

Complete when a user can retain an optional resource to investigate (right-of-way, crews/equipment, substation capacity or another stated question), next research action and analyst/owner text with their review. Empty fields remain optional. Valid user-entered impact inputs and the canonical result can be explicitly saved/exported with assumption labels; incomplete draft inputs stay editable and never masquerade as a computed result. Old saved reviews load unchanged; evidence refresh preserves notes and investigation work. No external sending or contact discovery.
