# F28-C2 — Facility extents, context and source-use agreement

Next enabling assignment: coordinator defines and commits the shared agreement before a facility producer or parallel consumers start. Inputs are B2's [qualification](osm-qualification.md), existing F28 point/area/review interfaces, retained full Census polygons, source-use requirements and the four-extract complete scope. Community-mapped facilities are a new unverified reference category; they must stay explicit and cannot be promoted to source-located project centers or strict candidates.

Exact contract ownership: `app/src/domain/geography.ts`, `geographic-drafts.ts`, `geographic-coverage.ts`, optional new `geographic-attribution.ts`, this spec, mission/roadmap/tech-stack and relevant local instructions. No automatic Dataset/Project.location rewrite, map/UI edits, acquisition, package installation or calculation copies during agreement. Map and UI owners receive separate exact consumer specs after the contract is committed; core remains authoritative for matching/precision/proximity.

Agree source node positions versus actual supported facility footprints/bounding extents, including multipolygons and multiple sites; never substitute a centroid or invented route. Identify method, community provenance, null accuracy, precision and limitations. Preserve native evidence and reviewed decisions. Define state/territory context from authoritative Census polygon containment/intersection, including islands/holes, cross-boundary uncertainty and unsupported territory; extract clipping boxes cannot supply identity/context. Unique native type/ID/version and full raw/duplicate/emitted/excluded accounting apply across all four complete extracts.

Define machine-readable reference licence/attribution metadata, derivative/download offer and mixed companion/JSON/CSV/report behavior before runtime use. Preserve private analyst work and independent source meanings; no automatic public upload. Prefer a separately identifiable reusable reference asset and streamed extraction over an unbounded custom node map. Producer dispatch also needs available disk for 12.26 GB originals plus intermediates and an isolated approved Osmium runtime. Initial batches connect early, but completion covers the entire declared inventory.

Completion: a backward-compatible validated shared contract and exact producer/core/UI/map follow-ups, source/context/precision precedence and export meanings are concrete; current runs/drafts/source records remain accepted. Source qualification is complete, while no runtime OSM facility or acquisition is claimed until these dependencies are implemented. Subsequent verification stays with the coordinator and the existing bounded policy.
