# F27-L1 — Load large collections without blocking the application shell

Purpose: the integrated source inventory produces a 39.3 MB initial JavaScript chunk. Let the shell render while collection data loads, keep real/demo work isolated, and provide a recoverable failure state without discarding active revisions or drafts. This is an enabling consumer increment for the selected national inventory, not a new product direction.

Dependencies: PR111's complete data baseline and current source contracts. Regional producers continue only in their owned data files. Coordinator owns `app/src/data/provider.ts`, new `app/src/data/real/provider.ts`, new `app/src/data/demo/provider.ts`, this spec, technical agreement/roadmap and integration receipt. After TVA full delivery, UI owns exactly `app/src/App.tsx` and `changes/F27-loading-ui.md`. No Explorer, map, schema, calculation, source-session, package or generated component edits. Only coordinator checks.

Shared interface: `loadDataset(mode: DataMode): Promise<Dataset>` returns the same validated canonical collection. Cache successful results and in-flight work per mode; evict failed promises so retry can acquire data again. Real data uses browser-native JSON asset requests and the existing `datasetSchema` / `combineSourceDatasets`; exact static `new URL(path, import.meta.url)` declarations let Vite preserve hashed build assets and let the representative case read those same URLs from disk. `loadSourceDataset(readJson = defaultFetchReader)` accepts a reader returning unknown data, validates every input and the final mode, and never returns a partial collection on failure. Demo construction loads only when requested and preserves every fixture. No duplicate source composition or calculation engine; future provider connections edit the real loader's source list.

UI receives the Promise contract. Render a concise loading/retry state within the existing viewport shell. Keep the active collection, badge, analysis and controls consistent while another mode loads; a failed switch must leave the active session usable. Commit a requested mode only after its data is ready, guard stale completions/unmounts, and reuse cached collections on return. Preserve the existing per-mode scenario and mounted workspace behavior. Do not clear a source override or saved revision because a bundled request failed or finished later. Initial saved-revision restoration and bundle loading may proceed independently; prepare an additive bundle offer only when both inputs exist. Restore supplied data must not discard the active override before the bundled collection is available. Retain existing write locks, explicit apply/reset behavior and local persistence error handling.

Completion: source JSON records are emitted as assets rather than embedded in the initial application script; demo generation is a separate lazy module. All source rows/IDs/evidence, synthetic fixtures, canonical candidate results and revised dataset round trips remain unchanged. Duplicate requests reuse one load; failed requests can retry; no silent partial dataset appears. Loading/error/switching states use the existing shadcn defaults and internal scrolling. Coordinator runs one build and one representative loader/data case in the next integration milestone; no browser, performance benchmark, screenshots, visual/mobile checks or new test infrastructure. Report actual output sizes, not an unmeasured speed claim.

Guidance: [Vite static asset handling](https://vite.dev/guide/assets#new-url-url-import-meta-url) and [dynamic imports](https://vite.dev/guide/features#dynamic-import). Static asset URLs and native JSON parsing keep data out of JavaScript compilation; this does not reduce the complete collection's transfer or memory requirements.

Integrated implementation evidence: PR125 combines loaders and UI with the complete TVA/CNMI/WAPA scopes. The sole build/case passed at 5fff2e6, preserving source/demo records, local revisions and candidates, exercising rejected-load retry and same-mode promise caching, and confirming 24 intact JSON assets with an 835,886-byte initial script. Source-inspected UI paths preserve pending/failed-switch sessions and wait for bundled data before clearing a revision. No browser performance, storage interactions or visual checks were performed.
